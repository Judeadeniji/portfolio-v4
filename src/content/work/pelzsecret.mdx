## Overview

PelzSecret started as a static template  a beauty brand storefront with no dynamic functionality. The task was to turn it into a functioning e-commerce system: products that load from an API, a cart that persists, payments that process, and a checkout flow that completes end-to-end.

## What needed to work

- Dynamic product catalog loaded from backend API
- Product detail pages with variants and pricing
- Shopping cart with persistence
- Payment processing (integrate with existing payment provider)
- Complete checkout flow from cart to confirmation
- Responsive design that preserved the original aesthetic

## Architecture

```
Astro (Frontend)
       ↓
  Backend API (existing)
       ↓
  Payment Provider
```

The existing backend API was already built  the challenge was connecting the static Astro storefront to it. Astro's hybrid rendering model worked well here: product pages could be server-rendered on request while the rest of the site remained static.

## Engineering challenges

### Connecting a static template to dynamic data

The original template had hardcoded product data. Every product card, detail page, and category listing needed to be rewritten to fetch from the API. This wasn't just a data swap  the template's HTML structure assumed static content. Dynamic data required conditional rendering, loading states, and error handling that the original template never anticipated.

### Payment integration

The payment flow needed to work with the client's existing payment provider. This meant understanding their API, handling webhook callbacks for payment confirmation, and managing the state between "user clicked pay" and "payment confirmed." Race conditions between webhook delivery and user redirection needed careful handling.

### Checkout flow completeness

A checkout flow has many edge cases: what happens when a user closes the tab mid-payment? What if the payment succeeds but the confirmation email fails? What about inventory changes between cart and checkout?

Each of these scenarios needed explicit handling. The system needed to be resilient  partial failures shouldn't lose the user's order or charge them without confirmation.

## What I shipped

- Dynamic product catalog connected to backend API
- Product detail pages with variant selection
- Shopping cart with session persistence
- Payment integration with the existing provider
- Complete checkout flow with error handling
- Deployment and end-to-end verification

## Outcome

The resulting system handles the complete e-commerce flow from product discovery through checkout and payment confirmation, transforming a static template into a functional storefront.
